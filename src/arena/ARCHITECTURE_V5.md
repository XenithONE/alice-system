## 1. 内装（R2）

### C-INT-1 内装は**7番目の `MountFace: "internal"`**。新 `PartCategory` は作らない。

⚠ **発注者（Claude）の当初の理由付けは誤りだった。訂正して記録する。**
「新カテゴリは53箇所の登録が必要で、漏らすと実行時に壊れる」と書いたが、両方とも違う。
- 新カテゴリを足すと `assemble.ts:366` の `isSpear(def)` で **TS2345 のコンパイルエラー**になる
  （`def` が `WeaponDef | InternalDef` に絞られるため）。**静かには壊れない。**
- 新しい分岐が必要な箇所は **9箇所**（うち2つはコンパイル強制）。53は約6倍の過大評価だった。
- 面ルートは **14箇所（うち5つがコンパイル強制）**で、**編集量では安くない。**

**それでも面を選ぶ。理由は編集量ではなく設計にある:**
> 7番目の面は「内装が船体内部の**容積を占める**」ことを一級の空間制約にする。
> 6番目のカテゴリはパーツを与えるが**機関室を与えない**。機関室こそが機能である（「内装も弄れる」）。
> そして内部セル数は、`+=` を暴走させない**3つ目の上限**になる（C-INT-2 参照）。

なお `ARCHITECTURE_V4.md` で既に6番目のカテゴリ `"structure"` を約束しているので、
「新カテゴリは禁止」という立場は取っていない。**理由を正しく述べること。**

面の登録先で**静かに壊れる**のは以下（いずれも if/else 連鎖で、
**最後の裸の分岐が「rear」を意味する**ため、内装が背面として扱われる）:
`build.ts:15 VALID_FACES` / `:127 faceSize` / `:219 driveSide` /
`assemble.ts:138 faceHalfExtents`（**パーツの height が Z 方向の厚みになる**）/
`render/mounting.ts:5,55` / `builderScene.ts:163,252` /
⭐**`builder/storage.ts:7 FACES`（最悪）**——未知の面を `"deck"` に強制するので
**ガレージ保存と共有コードを往復するだけで内装がデッキに瞬間移動し、
「重複しています」という的外れなエラーが出る**。プレイヤーはビルダーが壊れたと思う。

コンパイルで守られるのは5箇所（`faceLabel` / `partLocalPosition` / `faceNormal` /
`builderScene` の `views` / `BuilderPanel` の `FACE_ICONS`）。

### C-INT-0 プリセット8体を殺さないための必須ルール

### C-INT-2 4つの収支は `+=`（プール加算）

### ⭐⭐ C-REACT 開始時の暴走回転の正しい直し方（発注者の当初案は**逆効果**だった）

**訂正。** 「スピンアップをランプにすれば反力が緩む」という当初の指示は**誤り**である。
角運動量は保存するので、ロータに与える角力積 `∫τ dt = I_rotor · Δω` は**ランプ形状に依らず一定**。
線形の角減衰 `d = DRIVE_ANGULAR_DAMPING = 0.9` の下で機体が振られる**総角度**は
```
θ_total = (∫τ dt) / (I_chassis · d) = I_rotor·Δω / (I_chassis · d)
```
で、**ランプの長さに依存しない**。それどころか有限窓での累積は
`ω_ss·(T − 1/d)` なので、**ランプを伸ばすほど総回転は増える**:
- τ=55 N·m を 3.45 秒 → 約 **468°**
- τ=19 N·m を 10 秒 → 約 **616°**

つまりランプは「1秒間の測定値」だけを良く見せて**機械としては悪化させる**。
⚠ **ランプ単体を修正として出荷してはならない。**（R2 のエンジン結合には引き続き必要だが、
それは手触りの話であって不具合の修正ではない。）

**正しい修正: 接地摩擦による反作用ブレーキ（3軸）。**
現状 `DRIVE_TRACTION_ASSIST`（`driver.ts:145-152`）は `y: 0` の線形インパルスのみで、
**スピナーの反力が床へ抜ける経路が sim に1本も無い**。項が欠けている。足すのは不正ではない。

毎ステップ、指令中で未到達のロータについて
`τ_i = min(τ_limit_i, I_i·(ω_target − |ω_measured|)/FIXED_DT)` を推定し、
`−axis_i·τ_i` を機体ローカルで合計して、**軸ごとに物理的な上限で飽和**させてから
`applyTorqueImpulse` する。

| 軸 | 上限 | spin-king | drum-runner |
|---|---|---|---|
| ヨー(Y) | `μ·m·g·トレッド半幅` | 1.1·112·9.81·0.36 ≈ **435 N·m** vs 反力55 | — |
| **ピッチ(X)** | `m·g·ホイールベース半長`（転倒モーメント） | — | 82·9.81·0.30 ≈ **241 N·m** vs 反力70 |
| ロール(Z) | `m·g·トレッド半幅` | | |

⭐⭐ **`drum-runner` はヨーではなく「前転」している。**
`drum-std` は `spinAxis: "vertical"` で `front` 面なので、反力軸は機体ローカル **X**＝
**駆動輪の車軸そのもの**（`assemble.ts:333`）。駆動系が**まったく拘束していない唯一の自由度**で、
しかもシャーシ剛体は約34kgしかない（車輪は別ボディ）。だから 232 kg·m²/s が入ると宙返りする。
→ **ヨーだけ押さえる実装では drum-runner は直らない。3軸すべてに要る。**
→ **ヨーだけを測るゲートは、宙返りしている機体を合格させる。**

浮いている／ひっくり返っている間は効かせない（`groundedFactor`）。
脱落した駆動は数えない。`REACTION_GRIP = 0.90` で全体を絞る。

⚠ `bot.chassis.mass()` は**車輪を含まない**（別ボディ）。総質量は組み立て時に合算し、
脱落時に再計算すること。含めないと**一番宙返りしやすい軽量機で一番ブレーキが効かない**。

## 2. 設置物（トラップ）

### C-DEP-1 **静的コライダー**。剛体にしない。
`createArenaSim` で**共有の固定ボディ `deployAnchor` を1つ**作り、
全ての設置物はその上のコライダーとして `setTranslation` で置く。
コスト **+1 ボディ、+N コライダー**。固定なので broadphase が再ソートしない。
（4席×8個を剛体にすると +128 ボディで現在の世界（約59）の倍以上。`avgStepMs < 4` が割れる）
衝突グループは `DEBRIS_COLLISION_GROUPS` を**そのまま**使う
（全席＋所有者自身＋床＋破片に当たる。`botCollisionGroups` は無改修）。

### C-DEP-2 **センサーではなく実体（solid）**。
決め手は**オイル**。センサーは摩擦を変えられないので、重なった全機体の全駆動コライダーの
`friction` を書き換えて復元する状態管理が要る（KO時・脱落時・期限切れで正しく巻き戻す必要がある）。
実体パッドに `friction 0` ＋ `CoefficientCombineRule.Min` を設定すれば
実効摩擦が `min(1.45, 0) = 0` になり、**機体側の状態を一切持たずに済み、離れれば自動で戻る**。
接触は既存の `CONTACT_FORCE_EVENTS` 経路で受ける（`sawColliders` と同じ形）。

⚠ 実体である以上パッドは段差になる。`DEPLOY_PAD_HALF_HEIGHT = 0.012`（全高24mm）に抑え、
**G-DRIVE-PAD**（パッド4枚を直進通過して最高速の9割を維持）で恒久的に縛る。

### C-DEP-3 上限と寿命
`DEPLOY_CAP_PER_SEAT = 5` / `DEPLOY_CAP_GLOBAL = 20` / `DEPLOY_TTL = 25` /
`DEPLOY_MIN_SPACING = 0.45`。**専用の配列と掃除処理**を持ち、
`MAX_DEBRIS = 24` の戦闘破片 FIFO とは**絶対に共有しない**
（共有するとスピナーの破片シャワーが地雷原を丸ごと追い出す）。
退役は**席ごとの FIFO を先**に効かせる。

### C-DEP-4 種別ごとの効果
- **マキビシ**: 相手コライダーが `ownerByCollider` で `category === "drive"` に解決したときだけ
  `damageTarget`。非駆動には何もしない。`CALTROP_DAMAGE 15` / `armorFactor 0.5` / 6回で消滅。
- **オイル**: ダメージなし・消耗なし。`friction 0` + `Min` と、駆動アシストの減衰のみ。
- **地雷**: `MINE_ARM_SEC = 1.0` の作動遅延あり（設置者が自分で踏む事故を防ぐ）。
  `MINE_DAMAGE = 120` は **`MAX_HIT_DAMAGE = 140` より意図的に低い**。
  **KO はダメージではなく `MINE_IMPULSE` でピットへ飛ばす／ひっくり返すことで取る。**
  クランプ回避のために `damageTarget` を多重に呼ぶような細工はしないこと。
- **粘着**: 席ごとに初回接触1回だけ `pinnedFor` を付けて消滅。

## 3. 投射物（ネット・ハープーン）

動的ボディ。**全体で同時4発まで**、TTL 2.2秒、CCD 有効、`DEBRIS_COLLISION_GROUPS`。

**ネットは速度をゼロにしない。** ゼロにすると他機が跳ね返るビリヤード球になり、
フリッパーで打ち上げるという一番面白い反撃が消える。代わりに
`driveDisabled`（駆動モータだけ停止・**武器は動き続ける**）＋減衰の引き上げ。
⚠ 期限切れで減衰を戻すときは**キャッシュした値ではなく `balance.ts` の定数を書き戻す**
（拘束が重なると壊れる。G-NET/5 がこれを検査する）。

回転武器が生きていることは飾りではない。`IMMOBILE_WEAPON_OMEGA` の存在により
**回っているスピナーは行動不能KOを自分で防ぐ**ので、拘束されても詰みではない。

## 5. ハープーンのウインチ ⭐**`updateClamps` の流用は却下**

`updateClamps` は毎ステップ `victim.setLinvel(attackerVel + (ap - vp) * 3)` を書く。
0.3m のクランプでは目立たないが、4m のケーブルでは:
1. **長さの項が無い** — 距離×3 で指令するので 4m なら 12m/s、めり込んで到着する
2. **反作用が無い** — 運動量が無から湧く。40kg が 120kg を引きずって自分は動かない＝トラクタービーム
3. **完全上書き** — 被害者の操作が消え、反撃できない。しかも
   「引かれている間だけ `IMMOBILE_SPEED` を超える」ので**KO判定の挙動が状況で変わる**

⚠ `JointData.rope` / `.spring` は 0.19.3 に存在するが、
`RopeImpulseJoint`/`SpringImpulseJoint` は `ImpulseJoint` を直接継承しており
**モータも長さ設定も持たない**。巻き取りには使えない。

**正: 関節を作らず、質量で分配した有界インパルス。**
```
n = 正規化(attackerPos − victimPos)
巻取り: 必要な closing 速度に足りない分だけ、TETHER_MAX_FORCE を上限に
        victim に +n、attacker に −n の**対のインパルス**（作用反作用）
張り  : L > TETHER_MAX_LEN のとき、離れる方向の相対速度成分だけを質量比で除去
切断  : 相対インパルスが TETHER_BREAK_IMPULSE(340 > CLAMP_BREAK_IMPULSE 260) を超えたら解放
```
`mReduced = m1·m2/(m1+m2)` で質量分配が自然に出る。
**軽い機体が重い機体を撃つと自分が引き寄せられる**＝物理的に正しく、戦術的にも面白い
（軽量機の接近手段になる）。インパルスなので**被害者は駆動で抵抗でき**、
`linvel` が `IMMOBILE_SPEED` を超えたままなのでKO判定の挙動も一貫する。

## 6. protocol v4

`PROTOCOL_VERSION = 4`。バージョン不一致の拒否（`session.ts:284,559`）は**機能**である
（v3 ゲストは「地雷が見えない試合」ではなく明示的なエラーになる）。

### 3つの運び方を分ける（1本の実体配列にしない）
| データ | 寿命 | 運び方 |
|---|---|---|
| 機体の状態（拘束/粘着/オイル/係留） | 毎tick変化 | **`BotSnap` のフィールド**（`burn` の前例） |
| 飛行中の投射物 | 毎tick移動・最大4・2.2秒 | **`proj[]` を毎スナップショット** |
| 設置済みパッド | **動かない**・25秒・最大20 | **`dep[]` をバージョンゲート** |

静止したパッドの座標を毎秒20回×25秒＝**同じ数値を500回**送るのは無駄。
`dv`（変化するたび増える版番号）を毎フレーム送り、`dep` は**変化時と
`DEP_KEYFRAME_TICKS = 100`（5秒）ごとのキーフレーム**のみ。
実測: 常時送信 +1168B/フレーム に対し、バージョンゲート **+31B/フレーム**（**37倍の節約**）。

定常フレームは 1701 → **約1987B（+17%）**、キーフレームで約3155B。

⚠ **キーフレームは必須**（§0-6）。`App.tsx` がシーンを作り直したとき、
再生されるスナップショットがキーフレームでないと**その試合中ずっと設置物が見えない**。

## 8. 恒久ゲート

**すべてのゲートは「壊し方」を1つ持ち、レビュー時に実際に赤くして見せること。**
一度も落ちたことのないゲートはゲートではない。

- **G-TRAP**: 上限・専用プール・駆動限定ダメージ・オイルの滑走・地雷の1回性・
  作動遅延・**ハンドル再利用**（設置物を消してから破片を大量発生させ、
  `trap` 効果のヒットが出ないこと）
- **G-NET**: 拘束中に動けない／**行動不能KOが出ない**／**回転武器は生きている**／
  拘束側に control が入る／**2連続拘束の後に減衰が完全に戻る**／
  `immobileFor` が**リセットではなく凍結**されている
- **G-HARPOON**: 距離が単調に縮み `TETHER_MIN_LEN` で止まる／
